# Carrier Navigator: аудит механизмов

Дата: 2026-11-06. Реализовано изолированное Lua-ядро маршрута и защиты.
Ниже отдельно указаны статические результаты и оставшаяся интеграция.
Работа мода в игре пока не подтверждена.

## Подтверждённые требования

Отдельный мод: маршрут авианосца, выбор скорости и автоматическое включение
защитного вооружения. Источники обнаружения угрозы — радар **ИЛИ** визуальный
контакт. Ни один из источников не обязателен при наличии другого.

Автоматика должна получать контакты, известные команде, а не перечислять всех
противников из серверного мира. Последняя известная позиция и ранее раскрытый
тип сами по себе не доказывают, что угроза обнаруживается сейчас.

## Что найдено

| Механизм | Свидетельство | Практический вывод |
| --- | --- | --- |
| Ввод маршрута | Установленный Revolution, `screen_holomap.lua`: `add_waypoint`, `clear_waypoints`, чтение позиций точек | Использовать штатные точки; следование человеческого авианосца этим точкам ещё не доказано |
| Отображение пути | Там же: `get_waypoint_path()` | Кандидат для отображения рассчитанного игрой пути; обход суши требует отдельной проверки |
| Скорость | Штатный `screen_propulsion.lua`: `get_velocity_magnitude() * 1.94` | Единицы интерфейса — узлы; заданную скорость отличать от фактической |
| Тяга SDK | `cc2.carrier.throttle(-1/0/1)`, шаг рычага 0.025 | Это изменение положения рычага, не команда скорости и не управление рулём |
| Защитные системы | Штатные `screen_weapons_anti_air.lua`, `screen_weapons_anti_missile.lua`; именованные `carrier_weapons_active_*` в модели авианосца | Сначала сопоставить реальные защитные установки с переключателями; не включать все оружейные слоты подряд |
| Видимые контакты | Штатный `screen_vision_radar.lua`, `get_radar_targets()` | Для машин проверяются `get_is_visible()` и `get_is_observation_revealed()`, для ракет — `get_is_visible()` |
| Кнопки SDK | `cc2.world.buttons()` / `set_buttons()` | Изменения разрешены в событии `vehicle_controls`; сервер должен проверять применимость и права |
| Независимый Lua SDK | `sdk/cc2.lua`, `include/cc2x.h` текущего 0.9.0-dev | Нет опубликованных координат точек, непрерывного управления рулём и командных контактов обнаружения |
| Штатный автопилот | Проверенный EXE 1.5.18-r2: ветвь движения авианосца выбирает штатный путь при `control_mode == 0`, физический штурвал при `control_mode == 1` | Само наличие ветви подтверждено статически; ещё проверить переход режима, ручной перехват и сохранение |

Проверка EXE реализована в отдельной рабочей ветке SDK `codex/carrier-navigation`
(`../cc2x-navigation` относительно корня проекта). Проверяются полный SHA-256,
PE-профиль, таблица виртуальных функций и байты обеих ветвей. Неизвестная версия
отклоняется. Установленный и опубликованный DLL не изменены.

Важная находка: выход `control_speed` передаётся в штатный поиск пути, но в
прочитанной ветви физики авианосца не виден как ограничитель крейсерской скорости.
Не считать простую запись этого поля работающим выбором скорости.

Важно: штатная пара `visible AND observation_revealed` — два игровых признака
одного контакта. Это **не** доказательство схемы «радар И визуальное наблюдение».
Их точный смысл, командную принадлежность и связь с обоими источниками надо
проверить в движке. Не переводить эти названия в придуманные флаги источников.

## Следующая реализация

1. Проверить штатное следование человеческого авианосца своим точкам и способ
   передачи руля автоматике, включая немедленный ручной перехват.
2. Получать маршрут и состояние движения из конкретного сохранения. Глобальные
   настройки модуля не использовать как хранилище маршрутов разных партий.
3. Подтвердить доступ к актуальным командным контактам независимо от открытого
   экрана. Закрытая карта не должна отключать обнаружение или защиту.
4. При нехватке SDK добавить общие проверяемые механизмы с одинаковыми C/Lua
   контрактами. Выбор скорости, определение угрозы и правила защиты оставить
   в этом моде.
5. Встраивать собственный интерфейс в проверенные версии голографической карты
   через расширения SDK. Не распространять изменённые копии экранов Revolution.

## Правила, ещё требующие решения

- Сопоставить подтверждённый состав (ПВО, CIWS, защита от торпед, контрмеры)
  с игровыми установками и штатным расходом контрмер.
- Когда обнаруженный вражеский контакт считается угрозой для авианосца:
  дальность, класс, входящий боеприпас. Нельзя подменять это правилом «любой
  противник на всей карте».
- Что делать после потери контакта. Автоматическое выключение не запрошено.
- Защита вне движения по маршруту; реакция на ручное выключение установки.

## Уже реализовано в ядре

`content/bridge/navigation.lua`: проверка и копирование маршрута, последовательные
точки, выбранная скорость в узлах, экспериментальный регулятор, замедление,
ожидание подтверждённого пути, ручной перехват и сброс при смене контекста.
Состояние можно получить как версионированную запись и восстановить на паузе
только при совпадении штатного маршрута. Это ещё не запись в сохранение игры.

`content/bridge/defence.lua`: достаточно текущего радара **или** визуального
контакта; скрытые, устаревшие, дружественные и неподтверждённые цели игнорируются.
Решения различают авиацию, входящие ракеты и торпеды. Учитываются ручная блокировка
систем и уже включённая защита. Модуль выдаёт запросы взведения; сам не стреляет
и пока не расходует контрмеры. Игровой исполнитель ещё отсутствует.

## Проверка перед игровой сборкой

Навигация: последовательные точки, повороты, изменение скорости, остановка,
ручной перехват, сохранение/загрузка и выпуск/приём авиации в движении.

Защита: только радар, только визуальный контакт, оба источника, скрытая цель,
устаревший контакт, дружественная цель, отсутствие подтверждённого контакта,
закрытая карта и смена сессии. Отдельно подтвердить сетевые права отправителя.

Пока эти механизмы не связаны и не проверены, считать проект исследовательским,
не готовым автопилотом или готовым автоматическим ПВО.
